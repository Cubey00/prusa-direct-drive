# printerproject

Python control of a Prusa Core One (as a gantry) with an IDS camera and a strain gauge read via printer metrics, for automated imaging and force-touch probing.

## Code
All user-facing text (UI, messages, file names, test part names) and the guides are in English, so anyone can use them.
- `GUI.py` – Tkinter app tying everything together (jogging, photos, gauge calibration, touch probing).
- `machine_settings.toml` + `machine_settings.py` – the ONE place for values that depend on the physical setup: PrusaLink address/user (`[prusalink]`, password stays in the app), filament (`[printing]`), bed and usable area, raster, fiducials, nozzle→sensor offset, sensor size, camera mm/px, force limits, calibration tolerances. `SETTINGS` is loaded and validated at import (clear `SettingsError` with section/key); `slicing/config.py`, `pathprogrammer/config.py`, `gantry_controls.Z_MAX` and the `force_guard` calls read from it. `measured = false` marks guesses. `PRINTERPROJECT_SETTINGS=<file>` loads another file. Change values in the TOML, not in the config modules.
- `docs/calibration-plan.md` – plan for the Calibrate button after the tool swap: setup calibration (offsets, camera scale), per-plate F1–F3 calibration (Z touch, XY via camera/tactile search, Z plane, acceptance criteria that block measuring, saved per plate), drift checks.
- `docs/connecting-the-printer.md` + `printer_network/` – how any laptop connects (guide, Windows + macOS). TU wall ports isolate devices, so the printer is on a direct Ethernet cable with fixed addresses: printer 192.168.50.2 (set via `prusa_printer_settings.ini`, Settings > System > Load Settings from File), laptop 192.168.50.1 (`laptop_setup.ps1` as admin: static IP without gateway + inbound UDP 8514 firewall rule; `laptop_undo.ps1`). Every laptop uses the same address so the printer's metrics target stays valid.
- `gantry_controls.py` – USB serial link to the printer: connect, G-code send, home, relative moves, e-stop, `MotionController`. `with activity(label):` marks what holds the serial lock (connect, M334 force-data setup, homing, moves, touches) and `_send` records the last command; `busy_text()` puts both in words. The calibrator no longer refuses a goto/home/creep/step at once when the lock is held: `App._wait_for_printer` waits up to 30 s, sending `status` ok=True "Waiting to …: the printer is busy with …" every 3 s (shown in Measure and the wizard), then refuses with `busy_text()`. `device_session.DeviceLease` leaves an owner note (PID, time, argv) next to its lock file, so a refusal names who holds the printer. Every serial line (and each `activity` start/end) is appended to `%TEMP%\prusa-direct-drive-serial.log` (`gantry_controls.SERIAL_LOG`, rotated at 5 MB): the way to see where the hidden calibrator waits. `_wait_for_printer` keeps the lock it got (callers release it in `finally`), so the start-up M334 can't slip in between. `GUI.py` makes its `CalibratorClient(start=False)` and calls `start()` (hello + listening) only after `on_message` is set: the app sends its first command (e.g. the procedure's `home`) the moment it gets the hello, and before this that command was dropped and the app waited forever. A `--hidden` calibrator closes itself when its link drops (`CalibratorClient.on_lost`; `CalibratorServer.close` closes the connection too): before, a crashed or killed path programmer left an invisible calibrator holding the USB port and the force data.
- `prusalink.py` – `PrusaLink` client for the printer's PrusaLink API v1 (digest auth or `X-Api-Key`): `status()`, `upload(gcode, print_after=True)`, `pause/resume/stop(job_id)`. Separate from the USB serial link, which stays free while the printer prints. Tested against `tests/fake_prusalink.py`.
- `strain_gauge.py` – `StrainGauge` reads force values streamed from the printer over UDP metrics (`enable_metrics`).
- `touch.py` – `touch()`: force/depth touch, returns a `TouchResult`; forces in grams. Gauge data arrives late and contact is stiff, so continuous moves overshoot (≈ stiffness × speed × delay): fast approach to contact (M410), back off, slow re-search (`SEARCH_SPEED`), then a continuous press at the touch speed (M410 at the target force or depth). `expect_z` (previous contact, passed by `PrinterHardware`) lets the slow search skip the fast hit. Simulated in `tests/test_touch.py`. Each `TouchResult` carries a `trace` (t, phase, metrics Z, |force|) that lands in the run log. STOP in the path programmer sets a cancel event (touch halts with M410) and `PrinterHardware.close()` then returns to the Z at run start.
- The printer sends a G1's `ok` only once the move is **done**, not when it is queued. To watch the load cell during a move, send it with `gantry_controls._send_nowait()` and drop the pending `ok` with `_resync_serial()` (`halt_move` does this). Z1.53 is where the moves to the travel limit end (floor).
- Force guard (`gantry_controls.force_guard`): above `[forces] guard_trip_g` the bed drops (relative, G91) until under `guard_release_g`, but never more than `guard_drop_mm` (30) per trip; a force that stays high after a drop (drift) does not drop again until it has been under the trip level once. The hidden calibrator reports a trip to the path programmer as a `status` starting with "Force guard" (`ipc.GUARD_STATUS`).
- **M410 WORKS.** The printer firmware is modified so M410 is an immediate stop. Use continuous moves stopped with M410; do not chunk moves (tried before: makes the printer jittery) and don't blame overshoot on M410.
- `pathprogrammer/` – PySide6 app (`python -m pathprogrammer`): load a `.3mf`, rotate to a face, three-point face→machine calibration on the plate fiducials F1/F2/F3 (`calibration.py`: least-squares similarity fit, per-point residuals; opening a plate 3MF fills the face points from its `plate_NN.json`, the calibrator's "Send position as F1/F2/F3" buttons fill the machine points; selecting a plate in the Print plates box opens it; at start-up the last import (`plates/last_out` in QSettings, read back with `slicing.pipeline.load_result`) and its selected plate come back by themselves), "Start calibration" (`ui/calibration_wizard.py`, the only calibration control in the left panel; the F1–F3 coordinate fields are kept there hidden as data): choice at the start (remembered per laptop): all three cones, or "Only cone 2" (only F2 measured = shift only; F1/F3 filled in as F2 + their bed distance from F2 for this session; only `cone_F2` is saved, Measure derives F1/F3 from it again), or "Home X and Y only" when the calibration is known to be right (only offered with a saved calibration: IPC `home` {z, label "home"} = bed to the travel height, then `G28 X Y`, answered with `goto_done`; then "Go to point 1" hides the wizard, keeps the calibrator open so X/Y stay homed, and starts Measure's `hover_above_point(0)`); one step at a time per cone: "Go to cone N" (IPC `goto` to the head position predicted from `[sensor] offset_x/y/z`, first guess 0 / −40 / −80 mm: Z to the travel height first, then X/Y; `goto_done` comes back; for cone 1 with `home_xy`: `gantry_controls.home_xy()` = `G28 X Y` after the bed is lowered, never Z (Z homing probes with the nozzle and the sensor below it would hit the bed; Z motors stay on so Z is kept), then `M84 S1800` so X/Y aren't released after the firmware's 2 min idle (released X/Y lose their home and can be pushed by hand; the calibrator sets `M84 S120` back on close)), then a slow jogger in the wizard (IPC `jog`, 1/0.5/0.1/0.05 mm at 2 mm/s, the calibrator runs `motion.nudge`), then "Send position of cone N" (IPC `request_position`; the calibrator answers with `position`, or `status` with the reason it couldn't). After F3: "Calibration successful! … Position known" only when `calibration.validate` has no issues, and then `machine_settings.save_values` (validates before writing) saves the head position on each cone as the new standard (`[calibration] cone_F1..cone_F3` = [x, y, z], [] = none yet) plus the sensor offset measured from them (X/Y from the bed positions of the cones, Z from the cone tip height; `measured = true`). When a cone has a saved position, "Go to cone N" drives there (travel height first) and then to the saved Z + `[sensor] hover_clearance` (`goto` `z_final`), so the user only jogs ~1 cm down (jog steps 5/1/0.5/0.1/0.05 mm). Saved positions hold while the cones stay where they are; clear them after changing `[work_area]`/`[fiducials]`. Ordered touch-point programs (JSON), execute with a simulator or the printer. Pure-logic modules (`calibration`, `program`, `model_io`, `face_render`, `executor`, `ipc`, `hardware`) have no Qt dependency; UI is in `ui/`. Launches `GUI.py --link <port>` as the visual calibrator (sends head positions back over `multiprocessing.connection`); only one process may own the serial/UDP ports, so execution requires the calibrator closed. Limits/conventions in `pathprogrammer/config.py` (`FACE_Y_TO_MACHINE_SIGN`, `MACHINE_XY_BOUNDS` placeholder). Each run gets its own folder `<runs folder>/<run name>/` (chosen in the Files box, default `runs/`) with `run_log.json`, `images.json`, `heightmap.csv/png` and `images/point_<pt>_<k>.tiff`. `heightmap.py` z-buffers the visible face of the oriented mesh (face x/y = print XY, height above the model bottom = bed 0). Points have `image_step` (g or mm): `touch(image_step=, capture=)` presses in segments, each stopped with M410, and exposes (`hardware.snap`, `config.CAMERA_EXPOSURE_US`) with the bed standing still; `images.json` lists force and gantry XY in print (face) coordinates per image (`imagesave.ImageSaver` writes TIFFs in a thread).
- `slicing/` – dataset of `.3mf`/`.stl` parts (STL read as mm) → print plates (`python -m slicing <dataset> <out>`, e.g. `out` = `plates/`). The spacer blocks on the rail ends stop the head 51 mm early on the right and 61 mm early at the front; the team's firmware (separate repo Cubey00/prusa-direct-drive-firmware, 6.10.100; never clone it inside this folder or its parent) uses the same limits (nozzle X −2..201, Y 42..221; G28 probes the bed at (189, 52) and (194, 44)). So everything stays in `USABLE_AREA` = `machine_settings.toml` usable_x/usable_y (bed X 0–200, Y 56–219; the front strip keeps 3 mm clear of the probe points; Y max 179 because the sensor sits 40 mm in front of the nozzle and the head stops at Y 221; `machine_settings.py` checks at load that the usable area is reachable by the nozzle (`[printer] travel`) and by the sensor (travel + `[sensor] offset`)). Fixed raster in it (`config.py`: `MARGIN_X`/`MARGIN_Y`, `CELL_PITCH` 20 → 8×5 = 40 cells), row by row from the front-left; three fiducial cones in the side strips (F1 front-left, F2 front-right, F3 back-left of the usable area) to locate the plate later with the camera inside the tactile sensor. Rejects parts that don't fit a cell or need support (overhang check). Per plate: `plate_NN.3mf`, `plate_NN.json` manifest (bed coordinates of every part and fiducial tip) and G-code from `prusa-slicer-console` with `slicing/profiles/coreone.ini` (exported from PrusaSlicer ≥ 2.9; 2.6.1 installed here doesn't know the Core One) plus `--dont-arrange`, no supports, and `config.PRINT_SPEEDS` / `PRIME` as command-line overrides (the profile is Prusa's 0.20mm SPEED: walls 200, infill 300 mm/s, accel up to 7000 spoil 5-15 mm parts, so walls 40/60, small perimeters 30, infill 100, max 100 mm/s, accel 1000-3000; 1 skirt loop to prime the nozzle, 2 mm brim). `python -m slicing.testset` writes 30 simple test parts to `testset/`; `--mini` writes only two (`MINI_PARTS`: `square_5mm` and `dome_5mm`) to `testset_mini/` for quick first prints (all ignored by git). `slicing/pipeline.run()` does the whole run (clears old plate files in the output folder first); the path programmer's "Print plates" box (`pathprogrammer/ui/plates_panel.py`: "Import dataset..." / "Import test set" / "Import mini test set") calls it in a QThread, always slices right after the import into `plates/<dataset folder name>/`, and shows the plates from their manifests; "Show in 3D" opens the selected plate's G-code in `prusa-gcodeviewer.exe` (`slicer.open_in_viewer`). Filament: `slicing/filaments.py` resolves a filament preset (with its `inherits` chain) from PrusaSlicer's own bundle `PrusaResearch.ini` and slicing loads it after the profile (`--load coreone.ini --load filament.ini`), so another filament needs no new export; default in `machine_settings.toml` `[printing] filament` (now Generic PETG @COREONE HF0.4), dropdown in the Print plates box (remembered per laptop), `python -m slicing --filament NAME`. The printer refuses G-code whose `filament_type` differs from the loaded filament. Start of print: `slicing/startgcode.py` writes `start_gcode.ini` (loaded last) that swaps the profile's `G29 P1` (whole first-layer area + ~30 mm: 42 probe points on our plates) for one small `G29 P1 X Y W H [C]` box per `[printing] bed_probe_points` spot, snapped to the team firmware's probe grid (21×21 mesh X 2..198, Y 43..217, every 3rd point probed; read from the firmware repo), and drops `G29 G` (waits minutes until the bed frame is warm) unless `wait_for_bed_frame = true`, and moves the purge: Prusa draws it at X 249 -> 199, Y -2.5 (with the G29 P9 nozzle cleaning at X 208 and a purge-place probe box at Y 0..20), all unreachable behind the spacer blocks, so the parts started with an empty nozzle; every X of the purge section is shifted to start at `[printing] purge_start_x` (80) going 50 mm left at `purge_y` (47), the cleaning and probe box move along (`machine_settings` checks reach, the usable area and the G28 probe points); the start G-code's `G29 P3.2`/`P3.13` fill in the rest of the mesh. `check_compatible` refuses a profile whose `printer_model` isn't `COREONE` (e.g. the Core One L) or whose bed isn't 250×220. Printing: the "Printer (PrusaLink)" box (`pathprogrammer/ui/printer_box.py`) uploads the selected plate's G-code over the network and starts it, then polls the printer every 2 s (state, progress, time left, temperatures; pause/resume/stop). Login (address, user `maker` + password, or API key) is entered in "Printer settings..." and kept in QSettings on this computer only.
- Layout (`ui/main_window.py`, look in `ui/style.py`): left Print plates / Printer (green Print button, retries every 3 s so it connects soon after the printer is plugged in) / Calibration (blue button); centre "Photo control" (`ui/photo_panel.py` + `camera_feed.py`: live image, keeps trying to open the camera, "Take photo" saves a TIFF in `photos/` or the chosen folder; released while a run uses the camera), a small model preview and the folded "Model control"; right the folded points list, "Measure" (`ui/measure_box.py` + `measure.py`: "Do whole measuring procedure" (top row, with max force g / down per step mm / steps next to it, remembered per laptop as `measure/*` in QSettings; `MainWindow.start_procedure` chains the steps below: IPC `home` (X/Y only, saved calibration), then for EVERY part of the plate in manifest order (parts out of the sensor's reach are skipped up front): `point N` (travel height first), the creep (first touch = indentation 0), then `steps` × IPC `step` at the max force, a photo after each (500 ms settle, `PhotoPanel.take_tagged`, the next step waits for `photoSaved`); the max force ends that part (photo of that spot too) and a creep without contact skips it, both go on to the next part; any other error and STOP end it without moving; finally lifts back to 3 mm above the last part. One folder per run `<photo folder>/<YYYY-MM-DD_HH-MM-SS>/` with the photos, `measurements.csv` and `procedure.json` (settings, result, per part its result / steps / photos, and per photo file, time, point, object, step, indentation, force, head X/Y/Z, contact Z, bed X/Y), rewritten after every photo; Measure timeouts carry a token so an old timer can't end a later move); "Hover N mm above point 1" (approach settings below the procedure row, remembered as `measure/hover_mm`, `fast_speed`, `slow_zone_mm`, `slow_speed`; defaults in `measure.py`: 3 mm, 2 mm/s, last 1.5 mm at 0.1 mm/s; the creep IPC carries `fast_speed`/`speed`, fast part = hover − slow zone, at most hover + 5 mm) fits the plate's cone bed X/Y to the head X/Y on the cones (this session's calibration, else the saved `[calibration]` cones), drives over the plate at the travel height via the calibrator (`goto` label `point 1`, X/Y homed first after a calibrator start) and stops with the sensor `measure.HOVER_MM` (3 mm, was 1 cm: the creep took ~36 s) above the first part's top; after a point was reached "Go to next point" does the same for the next part in manifest order (goto label `point N`: travel height first, so the sensor lifts clear of every part, then X/Y, then down to 3 mm above): head Z = top + HOVER_MM - offset_z; refused until the sensor Z offset is measured; "Move very slowly until the sensor touches the object": IPC `creep` → `touch.creep_to_contact` in the calibrator: fresh tare, bed up at `CREEP_FAST_SPEED` 2 mm/s for the known-free `measure.CREEP_FREE_MM` (hover gap − 1.5 mm) after a hover, then 0.1 mm/s for the last 1.5 mm and on (~16 s instead of ~36 s), M410 on a quick force rise (`touch.RiseDetector`: `[forces] contact_rise_g` above the mean of `contact_rise_s`..2× that earlier, so load cell drift doesn't count; the rise must last `contact_hold_s` (0.2 s) so a spike doesn't count; after the M410 `_confirm` waits `contact_verify_s` (0.3 s) and if the force is no longer half of `contact_rise_g` above the baseline it was a false alarm and the bed goes on (`TouchResult.false_alarms`, error after `MAX_FALSE_ALARMS`); the known-free fast part only stops at `jog_stop_g`; at `jog_stop_g` anyway) and stay there; answered with `touch_done`; STOP sends `halt`); "Go 0.1 mm down" (only after that first touch, which sets indentation 0): IPC `step` → `touch.press_step` (bed 0.1 mm up, M410 at 300 g, refused when already there), answered with `touch_done` status ok/limit; the box shows object, indentation (contact Z − Z) and force. While a first touch exists, "Take photo" names the photo `photo_<object>_d<mm>mm_F<g>g_<time>.tif` (force = latest streamed force) and appends a row to `measurements.csv` in the photo folder (`PhotoPanel.tag_provider`), force graph (outside runs: the calibrator streams the tared force 10×/s over IPC `force`) and run controls (`ui/collapsible.py`, open/shut remembered). `PRINTERPROJECT_NO_CAMERA=1` (set in `tests/conftest.py`) keeps the camera off. Exposure time / gain in the panel (the 5 V LED lighting is external, not controlled) are remembered per laptop; the IDS camera needs the IDS peak SDK (driver, GENICAM_GENTL64_PATH) plus `pip install ids_peak ids_peak_ipl`. The Calibration box shows `[sensor] offset` above Start calibration; "Adjust..." (`ui/sensor_offset.py`) changes it only after a check box and typing ADJUST (saved with measured = false; the calibration measures it). The wizard starts `GUI.py --link <port> --hidden` (no window, errors go to the wizard as status) and closes it with an IPC `quit` when the wizard or the app closes. Start the app with the "Touch Path Programmer" shortcut (`python tools/make_shortcut.py` once per Windows laptop: pythonw, no console; logo from `tools/make_icon.py` in `assets/`).
- `tests/` – pytest (+ pytest-qt) for the path programmer; run `python -m pytest` from the root. `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen`: on macOS hidden Cocoa windows get App Nap, which stretches timers and makes timing tests fail at random.
- `ids_camera.py` – `IDS_Camera` wrapper around the IDS peak SDK.
- `imaging.py` – snap/save TIFF images (threaded saver); `set_photo_folder`.
- `gauge_drift_reader.py` – logs and plots strain gauge drift over time.
- `camera speedtester.py` – benchmarks the snap + TIFF save pipeline.
- `printer_command_test.py` – quick serial/G-code connection test.

## Data / other
- `How to start.md` – first-time setup for a new user: Python, git, requirements, PrusaSlicer, IDS peak SDK, network cable, shortcut, PrusaLink password, checks. Keep it in step with setup changes.
- `calibration.json` – hand-edited load cell `scale` (grams = scale × tared reading), read by `strain_gauge.py`; fit it with the GUI calibration points.
- `logs/` – drift logs (JSON) and plots, calibration plots.
- `fototest/` – sample TIFFs from a camera test.
- `MMConfig_demo.cfg`, `*.lnk` – Micro-Manager config and shortcuts (Micro-Manager, IDS peak Cockpit).
- `USB drive backup/` – unrelated backup: printer firmware (`.bbf`), sliced prints (`.bgcode`), knife/part CAD (`.dxf`), logos, coursework PDFs, test G-code.
