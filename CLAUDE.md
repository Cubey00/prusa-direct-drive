# printerproject

Python control of a Prusa Core One (as a gantry) with an IDS camera and a strain gauge read via printer metrics, for automated imaging and force-touch probing.

## Code
- `GUI.py` – Tkinter app tying everything together (jogging, photos, gauge calibration, touch probing).
- `machine_settings.toml` + `machine_settings.py` – the ONE place for values that depend on the physical setup: bed and usable area, raster, fiducials, nozzle→sensor offset, sensor size, camera mm/px, force limits, calibration tolerances. `SETTINGS` is loaded and validated at import (clear `SettingsError` with section/key); `slicing/config.py`, `pathprogrammer/config.py`, `gantry_controls.Z_MAX` and the `force_guard` calls read from it. `measured = false` marks guesses. `PRINTERPROJECT_SETTINGS=<file>` loads another file. Change values in the TOML, not in the config modules.
- `docs/kalibratie-plan.md` – plan (Dutch) for the Calibrate button after the tool swap: setup calibration (offsets, camera scale), per-plate F1–F3 calibration (Z touch, XY via camera/tactile search, Z plane, acceptance criteria that block measuring, saved per plate), drift checks.
- `gantry_controls.py` – USB serial link to the printer: connect, G-code send, home, relative moves, e-stop, `MotionController`.
- `prusalink.py` – `PrusaLink` client for the printer's PrusaLink API v1 (digest auth or `X-Api-Key`): `status()`, `upload(gcode, print_after=True)`, `pause/resume/stop(job_id)`. Separate from the USB serial link, which stays free while the printer prints. Tested against `tests/fake_prusalink.py`.
- `strain_gauge.py` – `StrainGauge` reads force values streamed from the printer over UDP metrics (`enable_metrics`).
- `touch.py` – `touch()`: force/depth touch, returns a `TouchResult`; forces in grams. Gauge data arrives late and contact is stiff, so continuous moves overshoot (≈ stiffness × speed × delay): fast approach to contact (M410), back off, slow re-search (`SEARCH_SPEED`), then a continuous press at the touch speed (M410 at the target force or depth). `expect_z` (previous contact, passed by `PrinterHardware`) lets the slow search skip the fast hit. Simulated in `tests/test_touch.py`. Each `TouchResult` carries a `trace` (t, phase, metrics Z, |force|) that lands in the run log. STOP in the path programmer sets a cancel event (touch halts with M410) and `PrinterHardware.close()` then returns to the Z at run start.
- The printer sends a G1's `ok` only once the move is **done**, not when it is queued. To watch the load cell during a move, send it with `gantry_controls._send_nowait()` and drop the pending `ok` with `_resync_serial()` (`halt_move` does this). Z1.53 is where the moves to the travel limit end (floor).
- **M410 WORKS.** The printer firmware is modified so M410 is an immediate stop. Use continuous moves stopped with M410; do not chunk moves (tried before: makes the printer jittery) and don't blame overshoot on M410.
- `pathprogrammer/` – PySide6 app (`python -m pathprogrammer`): load a `.3mf`, rotate to a face, three-point face→machine calibration on the plate fiducials F1/F2/F3 (`calibration.py`: least-squares similarity fit, per-point residuals; opening a plate 3MF fills the face points from its `plate_NN.json`, the calibrator's "Send position as F1/F2/F3" buttons fill the machine points; "Open plate in programmer" in the Print plates box opens the selected plate), ordered touch-point programs (JSON), execute with a simulator or the printer. Pure-logic modules (`calibration`, `program`, `model_io`, `face_render`, `executor`, `ipc`, `hardware`) have no Qt dependency; UI is in `ui/`. Launches `GUI.py --link <port>` as the visual calibrator (sends head positions back over `multiprocessing.connection`); only one process may own the serial/UDP ports, so execution requires the calibrator closed. Limits/conventions in `pathprogrammer/config.py` (`FACE_Y_TO_MACHINE_SIGN`, `MACHINE_XY_BOUNDS` placeholder). Run logs go to `logs/runs/`.
- `slicing/` – dataset of `.3mf`/`.stl` parts (STL read as mm) → print plates (`python -m slicing <dataset> <out>`, e.g. `out` = `plates/`). The stops on the rods block the front and back 60 mm of the bed (seen from the door), so everything stays in `USABLE_AREA` (bed X 0–250, Y 60–160). Fixed raster in it (`config.py`: `MARGIN_X`/`MARGIN_Y`, `CELL_PITCH` 20 → 10×4 = 40 cells), row by row from the front-left; three fiducial cones in the side strips (F1 front-left, F2 front-right, F3 back-left of the usable area) to locate the plate later with the camera inside the tactile sensor. Rejects parts that don't fit a cell or need support (overhang check). Per plate: `plate_NN.3mf`, `plate_NN.json` manifest (bed coordinates of every part and fiducial tip) and G-code from `prusa-slicer-console` with `slicing/profiles/coreone.ini` (exported from PrusaSlicer ≥ 2.9; 2.6.1 installed here doesn't know the Core One) plus `--dont-arrange`, no supports. `python -m slicing.testset` writes 30 simple test parts to `testset/` (both ignored by git). `slicing/pipeline.run()` does the whole run (clears old plate files in the output folder first); the path programmer's "Print plates" box (`pathprogrammer/ui/plates_panel.py`: "Import dataset..." / "Import test set") calls it in a QThread, always slices right after the import into `plates/<dataset folder name>/`, and shows the plates from their manifests; "Show in 3D" opens the selected plate's G-code in `prusa-gcodeviewer.exe` (`slicer.open_in_viewer`). `check_compatible` refuses a profile whose `printer_model` isn't `COREONE` (e.g. the Core One L) or whose bed isn't 250×220. Printing: the "Printer (PrusaLink)" box (`pathprogrammer/ui/printer_box.py`) uploads the selected plate's G-code over the network and starts it, then polls the printer every 2 s (state, progress, time left, temperatures; pause/resume/stop). Login (address, user `maker` + password, or API key) is entered in "Printer settings..." and kept in QSettings on this computer only.
- `tests/` – pytest (+ pytest-qt) for the path programmer; run `python -m pytest` from the root.
- `ids_camera.py` – `IDS_Camera` wrapper around the IDS peak SDK.
- `imaging.py` – snap/save TIFF images (threaded saver); `set_photo_folder`.
- `gauge_drift_reader.py` – logs and plots strain gauge drift over time.
- `camera speedtester.py` – benchmarks the snap + TIFF save pipeline.
- `printer_command_test.py` – quick serial/G-code connection test.

## Data / other
- `calibration.json` – hand-edited load cell `scale` (grams = scale × tared reading), read by `strain_gauge.py`; fit it with the GUI calibration points.
- `logs/` – drift logs (JSON) and plots, calibration plots.
- `fototest/` – sample TIFFs from a camera test.
- `MMConfig_demo.cfg`, `*.lnk` – Micro-Manager config and shortcuts (Micro-Manager, IDS peak Cockpit).
- `USB drive backup/` – unrelated backup: printer firmware (`.bbf`), sliced prints (`.bgcode`), knife/part CAD (`.dxf`), logos, coursework PDFs, test G-code.
